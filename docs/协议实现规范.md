# AirPlay 2 协议实现规范（特性矩阵）

> **本文档是重写的唯一规范。** 按特性点组织；每个特性点列出**每个参考**的结论：
> 有 = 怎么实现 + 代码位置；没有 = 为什么没有（或可能在的部分）；未逐行取证则如实标注。
> 参考可信度分级见 `research/references/REFERENCES.md`：**A 级** owntone-server（生产发送端）/ pyatv（生产发送端）/ shairport-sync（生产接收端，佐证"接收端接受什么"）；**C 级** airplay2-sender-cpp（`raop_sender.cpp`，仅代码字面）；**真机** = 本机 HomePod 实测（`research/06`）。
> AP1 参考（libraop/rust-raop-player）与 mDNS 库不逐点列出（路线/职责不同）；Sunshine 仅出现在 §12 采集。
> 决策（用户批准，不得擅改）见 `research/archive/02 §7`；设备事实见 `research/06`。

## 链路总览与顺序

```
mDNS/手动IP → 明文 GET /info → [新 TCP] transient 配对 M1-M4 → 同连接加密通道
→ SETUP(会话) → 事件通道(反向 TCP) → 〔顺序分歧点 §6.3〕 → SETUP(流) → SET_PARAMETER(音量)
→ UDP: 音频(0x60) / sync(0xD4 1s) / timing server(0xD2→0xD3) / 控制(0xD5→0xD6) / POST /feedback 2s
→ TEARDOWN
```

## 7. 计时

### 7.1 timing server：应答 0xD2 → 32B 0xD3

| 参考 | 结论 |
|---|---|
| owntone | `[0]=0x80 [1]=0xD3 [2]=req[2] 回显 [3]=0 [8..16]=req[24..32]（origin 回显） [16..24]=接收时戳 [24..32]=发送时戳`；服务**常驻、先于会话启动** `[代码: owntone airplay.c:2262-2330, 4314]` |
| pyatv | 同构，但 seq 字段**恒 7**（不回显）→ 接收端不校验该字段 `[代码: pyatv raop/protocols/__init__.py:102-145]` |
| shairport-sync | 无（其作发送侧时钟客户端的对应物在 player.c，未取证） |
| raop_sender(C) | 同构 |
| 真机 | 迭代#2 后服务先于流 SETUP 启动；**HomePod 是否发来请求未确认**（防火墙嫌疑未排除） |

**选定**：owntone 式（回显 req[2]）；establish 时先启动服务再发会话 SETUP。

### 7.2 sync 包（20B，1s 节奏，首包 0x90 后续 0x80）

布局：`[0]=type [1]=0xD4 [2..4]=0x0007（AP2 中未用） [4..8]=当前播放位置 BE [8..16]=NTP 秒+小数 BE [16..20]=当前 rtptime BE`

| 参考 | 结论 |
|---|---|
| owntone | ✅ `[代码: owntone rtp_common.c:309-344]`；位置字段 = cur_pos / pos（注释：rtptime 须与 RTSP 告知的起始 rtptime 一致） |
| pyatv | ✅ `[代码: pyatv stream_client.py:109-133]`；位置字段 = rtptime−latency / rtptime（语义一致）；节拍器 ~1s |
| shairport-sync | 接收端消费 sync（rtp.c），佐证布局 |
| raop_sender(C) | 同构 |
| 真机 | 未到达 |

### 7.3 时间模型（44.1kHz 下）

- NTP 定点：`ntp2ts(n) = ((n >> 16) * rate) >> 16` `[代码: pyatv raop/timing.py:24-31]`
- latency（lead）= 22050 + 44100 = **66150**（1.5s）`[代码: pyatv raop/protocols/__init__.py:28,51]`
- 锚点：start_ts = ntp2ts(now)；rtptime = head_ts − (start_ts − latency) = 66150 + 已发帧数 `[代码: pyatv raop/protocols/__init__.py:48-57]`
- 协商窗口 latencyMin=11025 / latencyMax=88200（双 A 级一致：owntone airplay.c:2628-2629 / pyatv airplayv2.py:136-137）
- owntone / raop_sender 同模型（C 级同源）。真机未到达。

## 8. 音频包

### 8.1 RTP 头（12B）

| 参考 | 结论 |
|---|---|
| owntone | `[0x80, 0x60, seq BE, rtptime BE, ssrc BE]`——**恒 0x60，无 marker** `[代码: owntone rtp_common.c:163-171]` |
| pyatv | **首包 0xE0**、后续 0x60；SSRC = rtsp.session_id（=randrange(2^32)）`[代码: pyatv stream_client.py:581-587; support/rtsp.py:87]` |
| shairport-sync | 接收端解析（rtp.c），佐证头形 |
| raop_sender(C) | 首包 0xE0 |
| 真机 | 未到达 |

**选定**：首包 0xE0（pyatv 惯例）；SSRC = streamConnectionID = 随机 u32（双源一致）。

### 8.2 ALAC 未压缩帧（16bit 立体声）

写入比特序（MSB-first）：`3b 元素=1(CPE) · 4b 0 · 12b 0 · 1b hassize=0 · 2b uncompressed_bytes=0 · 1b isnotcompressed=1 · 样本(16b×2ch MSB-first) · 3b END=7 · 0 填充至字节`

| 参考 | 结论 |
|---|---|
| owntone | 用编码库 `alac_encode`（airplay.c:2088），非手写位写器；帧格式由其库保证 |
| pyatv | **无 ALAC**：AP2 路径用 ct=1 PCM 原始帧（airplayv2.py:131） |
| shairport-sync | ✅ **Apple 官方解码器**逐比特佐证字段序 `[代码: shairport-sync alac.c:816-839]` |
| raop_sender(C) | 手写位写器 `[代码: raop_sender.cpp:1814-1837]`，与解码器逐比特一致 |
| 真机 | 未到达 |

**选定**：自实现位写器（05 白名单），按 shairport-sync 解码器字段序对拍（黄金样本测试）。

### 8.3 加密与线上布局

`[12B RTP 头][ct+16B tag][8B nonce 尾附]`；AAD = 头[4..12]（rtptime+SSRC）；ChaCha20-Poly1305，key=shk。

| 参考 | 结论 |
|---|---|
| owntone | ✅ nonce = **RTP 序号**（注释：重发包加密结果逐字节相同）`[代码: owntone airplay.c:1916-1950]` |
| pyatv | ✅ nonce = 内部 8B 计数器尾附（注释：曾发零 nonce，"Apple doesn't seem to care"）`[代码: pyatv raop/protocols/airplayv2.py:183-208; support/chacha20.py:50-76]` |
| shairport-sync | 接收端解密（rtp.c），佐证布局 |
| raop_sender(C) | 同构 |
| 真机 | 未到达 |

**选定**：nonce = seq（owntone 式；重传语义干净）。

### 8.4 发送节奏与静音续传

| 参考 | 结论 |

| 真机 | 未到达 |

**选定**：令牌桶 44100/s + 无块发静音（splice 纪律为 `[自定]`，pyatv 零包佐证方向一致）。
