## 1. 连接序列（真机验证）

- Native 连接序：`TCP → GET /info（明文）→ HAP transient 配对 → 加密 RTSP（[2B LE][ct+16B tag] ≤1024B，nonce=4零+8B LE 方向计数器）→ 加密 GET /info → session SETUP（timingProtocol NTP）→ eventPort 反向 TCP → RECORD → stream SETUP` `[实验: 06 —— 除 stream SETUP 外逐步真机通过]`。
- HAP 帧格式与 HKDF（Control-Salt/Events-Salt、64B SRP K 全量 IKM）：`[代码: owntone airplay.c:1443（注释明示 64B）; pair_homekit.c:2904-2913（事件通道密钥对调）; pyatv hap_transient.py encryption_keys]`。
- stream SETUP 响应**按键名解析 plist**（不依赖键序）：pyatv/owntone 均按字典键取值 `[代码: pyatv ap2_session.py decode_bplist; owntone wplist 按键读取]`——亦为基本工程常识。
- 发现层：浏览 `_airplay._tcp` + `_raop._tcp`；用户 HomePod 实际广告 `model=AudioAccessory6,1` `[实验: 06]`。features 位段语义仅以社区文档为背景 `[文档: airplay2-internals/index_features.html]`，实际路由决策以探测为准。

## 3. 协议细节（重锚后）

- **音频密钥规则**：`cipher key == stream SETUP plist 中的 shk`。owntone 惯例 = 共享秘密前 32B `[代码: owntone airplay.c:2630]`，采用之。（pyatv 用派生密钥亦可工作，说明接收端只认 shk 本身 `[代码: pyatv ap2_session.py]`。）
- **RTP 包布局**：`[12B RTP 头][密文][16B tag][8B nonce]`，AAD=头[4..12)，nonce=序列号置于 12B nonce 的 offset 4、尾部附同 8B `[代码: owntone airplay.c:1916-1950 packet_encrypt]`。pyatv 用 8B LE 独立计数器变体亦可工作 `[代码: pyatv]`——两变体择一即可，重传包与原包字节一致是共同要求 `[代码: owntone airplay.c:1931 注释]`。
- **sync 包**：节奏 ~1s；首包 0x90 后续 0x80 `[代码: owntone airplay.c:2184-2195]`；pyatv ~1s `[代码: pyatv stream_client.py]`。20B 布局细节重写时以 owntone `rtp_sync_packet_next` 定稿 `[待读: owntone rtp_session 代码]`。
- **计时应答**：32B，`[0x80, 0xD3, req[2], 0, ...]`，req[24..32] 原样回显至 [8..16]，收/发时间戳 `[代码: owntone airplay.c:2262-2330 timing_svc_cb]`。
- **音量**：-30..0 dB 线性、0 → -144 静音哨兵、`SET_PARAMETER volume:` `[代码: pyatv percentage_to_dbfs; owntone SET_PARAMETER volume]`。三实现一致。
- **RECORD 在 stream SETUP 之前**：owntone/pyatv 同序 `[代码: owntone airplay.c 会话序列; pyatv ap2_session.py:81-82]`。（"Samsung 不这样就无声"为 airplay-cli 孤证 → 删除，但顺序本身有 A 级一致支持。）
- **ct=2 ALAC 为 HomePod 路线**（决策 C）；ct=1 PCM 仅 Apple TV 有 pyatv 先例 `[代码: pyatv airplayv2.py]`，HomePod 无 PCM 证据。
- **MediaRemote/MRP**：HomePod 纯音频不需要 → 不实现（KISS）`[需求分析自定]`。
- **PTP**：推迟。届时以 owntone PTP 会话代码为准 `[代码: owntone airplay.c payload_make_setup_session_ptp]`；airplay-cli 的 gPTP 细节不再作为依据。
- **SSRC 取值规则**：原"NTP 会话 SSRC=streamConnectionID"为 airplay-cli 孤证 → 降级 `[未验证]`；重写时任取 u32，真机再校。

## 4. 冲击已冻结决策的证据——真机已结案

### 4.1 决策 C（音质天花板）

- hi-res 格式码（0x100000/0x80000/0x200000）仅见 airplay-cli 代码与 MA README（同组织，降级）→ 全部 `[未验证]`。
- **真机结案**：用户 HomePod realtime 仅广告 44.1/16/2（24/48k 仅 bufferStream）→ hi-res 对本设备 realtime 永久出局，44.1/16/2 基线落定 `[实验: 06]`。"按广告启用 + opt-in"政策保留为通用策略（用户批准的决策 C 修订）。

### 4.2 决策 E（transient on HomePod）——冲突已由真机解决

- airplay-cli 曾声称"Apple TV/HomePod 要求 PIN pair-setup 凭据，transient 无声"——**被真机证伪**：用户 HomePod（statusFlags bit2 置位且有 pk）transient pair-setup 成功、HAMK 校验通过 `[实验: 06]`。此为 airplay-cli 叙事不可信的直接证据之一。
- 决策 E 修订维持：首版仅 transient；PIN pair-setup 预案封存（触发条件=真机 transient 失败，未触发）。
