## 链路总览与顺序

```
mDNS/手动IP → 明文 GET /info → [新 TCP] transient 配对 M1-M4 → 同连接加密通道
→ SETUP(会话) → 事件通道(反向 TCP) → 〔顺序分歧点 §6.3〕 → SETUP(流) → SET_PARAMETER(音量)
→ UDP: 音频(0x60) / sync(0xD4 1s) / timing server(0xD2→0xD3) / 控制(0xD5→0xD6) / POST /feedback 2s
→ TEARDOWN
```

## 2. 配对（transient）

### 2.1 M1 请求构造（TLV8 `{Method:0, State:1, Flags:0x10}` + 头 `X-Apple-HKP: 4`，POST /pair-setup）

| 参考 | 结论 |
|---|---|
| owntone | M1 TLV = State(1) + Method(0x00) +（transient 时）Flags(0x10)；SRP 实例于此创建 `[代码: owntone pair_ap/pair_homekit.c:1219-1258]` |
| pyatv | **先发 `POST /pair-pin-start`**，再 M1 TLV = Method(0x00) + SeqNo(1) + Flags(Transient) `[代码: pyatv auth/hap_transient.py:49-56]` |
| shairport-sync | 接收端 `/pair-setup`：与 owntone 共用 `pair_ap`；无 PIN 时 transient，完成后 `shared_secret_len` 64 `[代码: shairport-sync rtsp.c:1776-1819]` |
| raop_sender(C) | 有：HTTP/1.1 POST `/pair-setup`，M1 Method+State，transient 再加 Flags=0x10；Content-Type `application/octet-stream`；`X-Apple-HKP: 4` `[代码: raop_sender.cpp:1022-1053, 1315-1330]` |
| airplay2-receiver | 接收端：M1 见 Flags==TRANSIENT(0x10) 则只做 M1–M4；PIN 缺省 `"3939"` `[代码: airplay2-receiver hap.py:513-541, 908-911]` |
| libraop / rust-raop-player / babelpod | 无 HAP transient（AP1 fruit / 第三方桥） |
| Sunshine / AudioMirror / airplay-spec | 无此发送流程 |
| 真机 | ✅ M1→M4 全流程成功（HAMK 校验通过，06）——**未发 /pair-pin-start 亦成功 → 该步对 HomePod gen 2 可选**。TLV 字段顺序：owntone State,Method,Flags / pyatv Method,SeqNo,Flags / raop_sender Method,State,Flags → 字段顺序无语义 |

**选定**：M1 = State=1, Method=0, Flags=0x10（owntone 顺序）；`X-Apple-HKP: 4`；Content-Type `application/octet-stream`；走 **RTSP/1.0 POST**（owntone 时序表 `[代码: owntone airplay.c:3697-3698]`）。pyatv/raop_sender 的 HTTP/1.1 配对是另一条同 socket 通路，本探针不走。`/pair-pin-start` 省略（真机）。PIN `"3939"`（owntone `pair_homekit.c:1176-1177`、pyatv `TRANSIENT_PIN`、airplay2-receiver 缺省）。M3 = State=3 + PublicKey(A) + Proof(M1)。M4 必须校验 HAMK（owntone `srp_user_verify_session`；pyatv transient **丢弃 M4 body**，不跟）。

### 2.2 SRP-6a 约定（RFC 5054 3072 位、生成元 5、SHA-512、用户名 "Pair-Setup"、k/u/x/M1/HAMK 公式）

| 参考 | 结论 |
|---|---|
| owntone | `USERNAME "Pair-Setup"`；`HASH_SHA512` + `SRP_NG_3072`（N 与 RFC 5054 A.4 一致，g=5）；`a` 256 bit；公式见 §16.2 `[代码: owntone pair_homekit.c:52, 195-223, 437, 1242]` |
| pyatv | `SRPContext("Pair-Setup", pin, prime=PRIME_3072, generator=PRIME_3072_GEN, hash_func=sha512)`，底层 `srptools` `[代码: pyatv hap_srp.py:138-155]` |
| shairport-sync | 与 owntone 同一份 `pair_ap`（client/server 均 SHA-512/3072） |
| raop_sender(C) | 自实现客户端：k/u 用 384 字节 PAD；K=SHA512(S 自然长度)；M2=H(A\|M1\|K) `[代码: airplay_crypto.cpp:266-398]` |
| airplay2-receiver | 服务端 `SRPServer`：k=H(N,g,pad=True)；K=H(S)；M1/M2 同构 `[代码: airplay2-receiver srp.py:32-121]` |
| libraop / rust-raop-player | AP1 fruit：SHA-1 / 2048。**不是本点** |
| 真机 | ✅ 约定成立（pair_ok，session_key_len=64） |

**选定**：自实现，公式以 owntone `pair_ap`（A 级）+ RFC 5054 PAD(k,u) 为准，细节 §16.2。S 的底数按 RFC 5054 先模 N（owntone 减法后直接 modexp；raop_sender 显式 `mod N` 保正）。K 为 64 字节 SHA-512(S)。

## 4. HAP 加密通道帧

帧 = `[2B LE 明文长][密文][16B tag]`；每块明文 ≤1024；nonce = 4 字节零 + 8 字节小端计数器；收、发计数器独立；AEAD 附加数据 = 那 2 字节长度。配对成功后**同一条 TCP** 上，先把整份 RTSP 明文封成帧再写；读则先拆帧解密，再在明文缓冲里解析 RTSP（禁止再对 TCP 逐字节扫 `\r\n\r\n`）。

| 参考 | 结论 |
|---|---|
| owntone | 有：`ENCRYPTED_LEN_MAX 0x400`；`encrypt` 按块写 `uint16 block_len`（主机序，Windows/Linux 小端即 LE）+ ChaCha20-Poly1305，AAD=`&block_len` 共 2 字节，tag 16 字节跟在密文后；nonce 12 字节先清零再 `memcpy(nonce+4, &encryption_counter, 8)`（小端主机即 4 零+LE 计数）；每块计数 +1。`decrypt` 对称。`rtsp_cipher` 把整份 RTSP 明文交给 `pair_encrypt` 再写入套接字 `[代码: owntone pair_homekit.c:53-56,2944-3051; airplay.c:1005-1045]` |
| pyatv | 有：`HAPSession.FRAME_LENGTH=1024`、`AUTH_TAG_LENGTH=16`；`encrypt`：`length = len(frame).to_bytes(2,'little')`，AEAD 的 aad=length，输出 `length + ciphertext+tag`。`decrypt` 从缓冲取 2 字节 LE 长度再取 `n+16`。`Chacha20Cipher` 默认 8 字节计数，左垫 4 零成 12 字节 nonce；收发计数独立。挂到 `HttpConnection.send_processor`/`receive_processor`，同一条连接 `[代码: pyatv hap_session.py:17-66; chacha20.py:15-73; http.py:385-387,457; airplay/auth/__init__.py:112-115]` |
| shairport-sync | 有（接收端）：`write_encrypted`/`read_encrypted` 调同一套 `pair_encrypt`/`pair_decrypt`；读侧把半帧留在 `encrypted_read_buffer` 直到 `pair_decrypt` 吃完整块 `[代码: shairport-sync rtsp.c:483-545]` |
| raop_sender(C) | 有：`writeRtsp_` 在 `controlEncrypted_` 后按 1024 切；2 字节 LE 长度；nonce8 为计数器小端 8 字节；AAD=那 2 字节；`chacha20Poly1305Encrypt` 再左垫 4 零成 12 字节 IETF nonce；线上 `len || ct+tag` `[代码: raop_sender.cpp:579-605; airplay_crypto.cpp:155-189]` |
| airplay2-receiver | 有（接收端）：`HAPSocket.MAX_BLOCK_LENGTH=0x400`；`struct.pack("H", length)`（小端主机即 LE）；nonce=`pack("Q", count).rjust(12, b"\x00")`；`cipher.update(pack("H", length))` 即 AAD=长度；`sendall` 写出 `length_bytes + enc + tag`。incoming 用 Write 钥（配件视角）`[代码: airplay2-receiver hap.py:1359-1506]` |
| libraop | 无 HAP 帧（AP1 `pair-setup-pin`，无 ChaCha 控制通道） |
| rust-raop-player | 无 |
| babelpod | 无 |
| airplay-spec | 背景：`pairing/hkp.md` 写 `N:n_bytes:tag`、N 为 16 位小端、每方向独立密钥与 nonce。**未写 AAD**。散文，帧形以 A 级代码为准 |
| Sunshine | 无（不是 AirPlay） |
| AudioMirror | 无 |
| 真机 | ✅ 当前 `crates/` 加密 GET /info 成功（06，`channel_ok`，body 2009） |

**选定**：按 owntone/pyatv（双 A 级 + 真机）：块长 1024；线上 `[u16 LE 明文长][密文][16B tag]`；AAD=那 2 字节长度；nonce=4 零 + u64 小端计数（从 0 起，每块 +1）；发送计数与接收计数分开；ChaCha20-Poly1305 IETF。加密开启后读路径按帧取，解密后再解析 RTSP。

## 7. 计时

### 7.1 timing server：应答 0xD2 → 32B 0xD3

| 参考 | 结论 |

### 7.2 sync 包（20B，1s 节奏，首包 0x90 后续 0x80）

| 参考 | 结论 |
|---|---|
| owntone | ✅ `[代码: owntone rtp_common.c:309-344]`；位置字段 = cur_pos / pos（注释：rtptime 须与 RTSP 告知的起始 rtptime 一致） |
| pyatv | ✅ `[代码: pyatv stream_client.py:109-133]`；位置字段 = rtptime−latency / rtptime（语义一致）；节拍器 ~1s |
| shairport-sync | 接收端消费 sync（rtp.c），佐证布局 |
| raop_sender(C) | 同构 |
| 真机 | 未到达 |

### 7.3 时间模型（44.1kHz 下）

- NTP 定点：`ntp2ts(n) = ((n >> 16) * rate) >> 16` `[代码: pyatv raop/timing.py:24-31]`
- latency（lead）= 22050 + 44100 = **66150**（1.5s）`[代码: pyatv raop/protocols/__init__.py:28,51]`
- 锚点：start_ts = ntp2ts(now)；rtptime = head_ts − (start_ts − latency) = 66150 + 已发帧数 `[代码: pyatv raop/protocols/__init__.py:48-57]`
- 协商窗口 latencyMin=11025 / latencyMax=88200（双 A 级一致：owntone airplay.c:2628-2629 / pyatv airplayv2.py:136-137）
- owntone / raop_sender 同模型（C 级同源）。真机未到达。

### 16.1 TLV8

规则：一字节 type、一字节 length（0–255）、value；同一 tag 连续分片，读时拼接。空 value 仍发 type+0。

| 参考 | 结论 |
|---|---|
| pyatv | `read_tlv` 把**所有**同 tag 拼进 dict（不要求相邻）；`write_tlv` 按 255 切 `[代码: pyatv hap_tlv8.py:77-123]`。Type：Method=0, Salt=2, PublicKey=3, Proof=4, SeqNo/State=6, Error=7, Flags=0x13；Flags.Transient=0x10 |
| owntone / shairport-sync | `pair-tlv.c`：写按 255 切；读只把「连续 255 块 + 同 type 收尾块」拼在一起 `[代码: owntone pair-tlv.c:116-207]`。Type 与 pyatv 同（Flags=19）；FragmentData 写成 13（HAP 规范是 12）——M1–M4 不用 Fragment |
| raop_sender(C) | 同 HAP 分片；decode 只拼接**紧邻**同 tag `[代码: airplay_crypto.cpp:404-438]` |
| airplay2-receiver | `Tlv8.decode` 同 pyatv（所有同 tag 拼接）；`encode` 接受 `[tag, value, tag, value, ...]` 列表 `[代码: hap.py:74-128]` |
| 其余在册参考 | 无 HAP TLV8 |

**选定**：编解码按 pyatv/airplay2-receiver（同 tag 全拼接，更容忍）。写出：len==0 发一条零长记录；len>0 按 255 切、不额外发零长尾（避免 airplay2-receiver `length % 255 == 0` 再写一条 0 的行为）。探针只用 Method/State/Salt/PublicKey/Proof/Flags/Error。

### 16.2 SRP-6a 客户端公式（HAP transient）

共同约定（双 A 级 + RFC 5054 A.4 + 真机）：N=3072-bit RFC 5054、g=5、SHA-512、I=`Pair-Setup`、P=`3939`、salt 16 字节、公钥 ≤384 字节、证明 64 字节。

| 量 | owntone `pair_homekit.c` / `pair.c` | raop_sender `airplay_crypto.cpp` | airplay2-receiver `srp.py`（服务端） |
|---|---|---|---|
| k | `H_nn_pad(N,g,N_len)`：两操作数左填到 384 再 SHA-512 `[pair.c:192-216]` | 同 PAD `[282-325]` | `H(N,g,pad=True)` |
| u | `H_nn_pad(A,B,N_len)` | 同 | `H(A,B,pad=True)` |
| x | `H_ns(salt, H(I:P))`：salt 当大数再 **去掉前导零** 后哈希 `[pair.c:218-232; pair_homekit.c:269-281]` | **原始 salt 字节**（不去前导零）`[327-336]` | salt 当 int，`to_bytes` 去前导零 |
| K | `hash_num(S)`：S 去前导零再 SHA-512，64 字节 `[508]` | 同「自然长度」`[352-353]` | `H(S)` 去前导零 |
| M1 | `H( H(N) xor H(g) \| H(I) \| s \| A \| B \| K )`，N/g/s/A/B 均去前导零 `[284-314]` | s/A/B 用自然长度；**s 用原始 salt 字节** `[355-373]` | 同 owntone（int 去零） |
| HAMK | `H(A \| M1 \| K)` `[316-327]` | 同 `[383-397]` | 同 `H(A,M1,K)` |
| A 上线 | `bnum_num_bytes(A)`，**不**填到 384 `[447-458]` | `mpi_write_binary` 自然长度 `[307-308]` | `to_bytes(B)` 自然长度 |
| S | `(B - k*g^x) ^ (a+ux) mod N`；减后**未**先 `mod N` `[500-506]` | 减后显式 `mod N` 保正 `[338-350]` | 服务端 `(A * v^u)^b mod N` |

**选定**：k/u 用 RFC 5054 PAD（三家一致）。x/M1 的 salt 与 A/B/S/N/g 按 owntone 去前导零（A 级；与 airplay2-receiver 一致；不跟 C 级「原始 salt 字节」）。S 底数减完后模 N（RFC 5054 数学形式；raop_sender 显式做了；owntone 依赖 BN_mod_exp 吃负数）。`a` 256 bit（owntone `bnum_random(a,256)`）。A 上线：自然长度，接收端检查 `size > 384` 才拒（owntone `pair_homekit.c:1436`），不强制填 384。安全检查：B≠0、u≠0。HAMK 用 `==` 比较（LAN + 公开 PIN；用户已定不改恒定时间）。

pyatv 的 `srptools` 是黑盒，行为以 owntone 为准。

### 16.3 bplist（探针只需解码 `/info`）

| 参考 | 结论 |
|---|---|
| pyatv | 编解码全部交给 CPython `plistlib.FMT_BINARY` `[代码: pyatv support/rtsp.py:10, 110, 287-288]`。整数：`tokenH==0x10`，宽 `1<<tokenL` 字节；`tokenL>=3` 按有符号；`tokenL==4` 读 16 字节。编码：`2^63..2^64-1` 写标记 `0x14` + 16 字节 `[文档: research/references/cpython_3.12_plistlib_int.md]` |
| owntone / shairport-sync | `libplist`：`plist_from_bin` / `plist_to_bin` / `plist_get_uint_val` `[代码: owntone plist_wrap.h; airplay.c:3301; shairport-sync rtsp.c:1258]`。整数宽度在库内，本树无实现 |
| raop_sender(C) | 自实现最小子集。整数最多 8 字节；`readBE` 进 `uint64`，16 字节会截断；UTF-16 只取低字节；根对象写死 index 0（忽略 trailer topObject）；扩展 count 不校验 marker 高半字节 `[代码: airplay_crypto.cpp:539-751]` |
| libraop | AP1 fruit 用的一层 dict 读写；整数按 32-bit `ntohl`，**不能**解 HomePod `/info` `[代码: libraop bplist.cpp:115-141]` |
| rust-raop-player / babelpod / Sunshine / AudioMirror | 无 bplist |
| airplay-spec | `/info` 字段表（string/int/real/bool/data）`[文档: get_info.md]`。样例 UA `AirPlay/380.10.1`，不作结论 |
| 真机 | `/info` body 2009 字节；`supportedFormats.bufferStream` 为 8 字节整数，位型 `0xf7fe018e00e80000`（按有符号 i64 看是负的，不是解码失败） |

**选定**：自实现解码，行为对齐 plistlib（A 级 pyatv 所用）：支持 dict/array/string（ASCII + UTF-16BE）/data/bool/null/real(4|8)/date(0x33)/UID/int（1/2/4/8/16 字节，8 与 16 字节有符号）。根对象用 trailer 的 topObject，不假设 0。扩展 count：后随整数对象的高半字节必须是 `0x10`。坏 UTF-8 有损替换（用户已定）。打印 8 字节整数时输出 64 位位型十六进制，禁止按 i128 符号扩展。编码（单测 round-trip 用）按 plistlib 宽度规则；探针 `/info` 不发 bplist body。

### 16.4 RTSP 请求帧（明文）

| 参考 | 结论 |
|---|---|
| pyatv | 行 `METHOD uri RTSP/1.0`；头 CSeq（从 0 递增）、DACP-ID（u64 大写 hex）、Active-Remote（u32 十进制）、Client-Instance（=DACP-ID）、User-Agent `AirPlay/550.10`；有 body 才写 Content-Length；响应按 Content-Length 取 body `[代码: pyatv support/rtsp.py:86-89, 254-300; http.py:50-80, 110-140]` |
| owntone | 同一套 `request_headers_add`：CSeq、UA（配置默认 `owntone/29.3`）、X-Apple-Client-Name、Client-Instance 与 DACP-ID 同为 `PRIX64`、Active-Remote 为 u32 十进制；Content-Length 由 evrtsp 加 `[代码: owntone airplay.c:889-933]`。配对另加 `X-Apple-HKP` |
| raop_sender(C) | RTSP/1.0 与 HTTP/1.1 配对都能发；RTSP 头含 UA `AirPlay/550.10`、DACP-ID、Active-Remote、Client-Instance、X-Apple-Client-Name `[代码: raop_sender.cpp:545-567, 1028-1044]` |
| libraop / rust-raop-player | AP1：`METHOD url RTSP/1.0` + CSeq + UA `iTunes/7.6.2 (Windows; N;)` + Client-Instance；DACP-ID/Active-Remote 可选 `[代码: libraop rtsp_client.c:585-607; rust-raop-player raop_client.rs:189; rtsp_client/mod.rs:324-344]` |
| shairport-sync / airplay2-receiver | 接收端：读 UA/DACP/Active-Remote 只打日志，缺头不拒 `/info` `[代码: shairport-sync rtsp.c:1174-1223; airplay2-receiver ap2-receiver.py:494-496]` |
| airplay-spec | 样例 `GET /info RTSP/1.0` + CSeq 0 + DACP-ID + Active-Remote + UA `AirPlay/380.10.1` `[文档: get_info.md]` |
| babelpod | 无自写 RTSP（依赖 `airtunes2`） |

**选定**：`RTSP/1.0`；CSeq 从 0；DACP-ID 与 Client-Instance 为同一 16 位大写 hex（u64）；Active-Remote 为 u32 十进制；User-Agent `AirPlay/550.10`（用户原话保持 550）；另加 `X-Apple-Client-Name: airplay`（owntone/raop_sender 有，pyatv 无；接收端不校验）。有 body 才写 Content-Length 与 Content-Type。响应：读到 `\r\n\r\n` 后按 Content-Length 取二进制 body；状态码非 2xx 抛错。`GET /info` 无 body（owntone SEQ_START、pyatv `info()`、raop_sender `sendAp2Info_`）。shairport Stage 1 带 qualifier plist 是可选的另一形态，发送端三家都不发。明文路径允许对 TCP 扫头；加密开启后改走 §16.5。

### 16.5 控制通道 HAP 帧（配对后同连接）

输入：64 字节 SRP K。输出：同一条 TCP 上的加密 RTSP。

构造：HKDF-SHA-512 出 32 字节 Write/Read 钥（§3.1）。发送时把整份 RTSP 明文按 1024 切开；每块 `n = u16 LE(块长)`，nonce = 4 零 + u64 LE 发送计数，AAD = `n` 的两字节，ChaCha20-Poly1305 IETF，线上 `n || 密文 || 16B tag`，然后发送计数 +1。接收时先读 2 字节 `n`，再读 `n+16`，用 Read 钥与接收计数解密（AAD 同样是那 2 字节），拼进明文缓冲，再按 Content-Length 解析 RTSP。计数从 0 起，收发分开。

证据与选定见 §3.1、§4。探针命令 `probe channel`：新 TCP → 明文 M1–M4 → 同连接打开加密 → 加密 `GET /info`。本切片不实现事件通道（§3.2）。
